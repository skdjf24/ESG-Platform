# Step 8｜定稿与导出验收

验收日期：2026-10-29  
开发基线：GitHub 最新 `feature/step7-1-quality-state-fixes-20261029`（`0ec609d`）

本轮直接在上述最新代码之后开发，没有建立第二套 Step 7 规则或状态。Step 8 只读取朋友版本已经提供的 `getStep8QualityGate(project)`。

## 实现结果

- 只有当前质量输入指纹、规则集指纹、成功全面检查和全部问题状态同时满足 Step 7.1 gate 时，才允许定稿。
- 定稿确认人、授权角色和四项人工声明必填，并明确说明原型记录不构成电子签名。
- `FinalReportVersion` 保存全面检查运行 ID、输入/规则指纹、问题快照、版式修订、页数、确认人和时间。
- 普通保存时间、项目修订号变化不会误判失效；披露输入、版式、规则或 Step 7 结论变化会使旧定稿失效。
- 失效版本保留为历史记录，但禁止继续打开正式输出或生成新归档包。
- 独立正式打印页不显示 blockId、编辑按钮、内部待办、Mock AI 或独立模拟数据说明。
- 浏览器可“打印 / 保存 PDF”；JSON 审计包包含版本元数据和完整来源快照，并明确标记 `simulatedPrototype: true`。
- 旧项目仅追加空的 `FinalizationState` 和一次迁移记录，Step 1–7 内容及质量历史不变。
- 接入 Noto Sans SC 本地字体，避免验收环境缺少中文系统字体造成方框字和分页漂移。

## 已知限制

- PDF 由浏览器打印保存，不是服务器端固定渲染文件；浏览器打印设置仍可能影响输出。
- 不生成 Word，不执行电子签章，不自动对外发布，也不连接正式档案系统。
- 身份和授权角色仍为手工输入，未接入真实权限、审批流或不可篡改审计服务。
- 项目和版本仍保存在浏览器 `localStorage`，不支持多人并发、服务端备份及正式恢复。
